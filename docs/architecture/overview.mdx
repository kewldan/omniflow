---
title: Architecture overview
description: Modular-monolith services, data flow, and integration boundaries.
---

Omniflow is a modular Go monolith with independently runnable processes:

- **API:** REST endpoints and incoming webhooks.
- **Bot:** Telegram updates and customer conversations.
- **Worker:** River jobs, reconciliation, fulfillment, campaigns, and notifications.
- **Admin:** Next.js operator application.
- **Portal:** Next.js customer application.

All durable state is stored in PostgreSQL. Valkey is limited to ephemeral state. River provides durable transactional work, while an outbox records domain events for future fan-out.

This architecture supports hundreds of open-source installations without imposing a broker, Kubernetes, or a plugin runtime on every operator.
