---
title: "0012 — Гостевые покупки — заказы-подарки одного системного аккаунта"
description: "Почему покупка без аккаунта использует механику подарков от гостевой кассы, а не создаёт клиента на каждый адрес"
---

**Статус:** принято.

## Контекст

Bedolaga продаёт посетителям без аккаунта: e-mail, оплата и ссылка активации.
В Omniflow каждый заказ принадлежит клиенту. Создание клиента на каждый
введённый адрес позволило бы кому угодно создавать аккаунты для чужих адресов,
чего вход по e-mail сознательно избегает, и оставляло бы пустые аккаунты за
каждой неоплаченной покупкой.

## Решение

**Гостевая покупка — заказ-подарок подписки от одного системного аккаунта**,
гостевой кассы. Оплата, истечение, возвраты и активация идут существующими
путями подарков. Код активации отправляется после оплаты и активируется
вошедшим клиентом; вход по e-mail с адресом плательщика — это и есть «активация
без пароля». Клиент появляется только тогда, когда входит владелец адреса.

Лендинги с собственной аналитикой по-прежнему отклонены.

## Последствия

- Один клиент — гостевая касса — владеет всеми гостевыми заказами и так и виден
  в отчётах и списке клиентов.
- Код — предъявительский: подписку получает тот, кто активирует первым. Он
  хранится зашифрованным только до отправки.
- Гостевым покупкам нужен e-mail-транспорт; без него они не предлагаются.

## Когда пересмотреть

Гостевым заказам понадобится отчётность по каждому покупателю (контакт для
возврата, доказательства по чарджбэку) сверх зашифрованного адреса плательщика —
это будет доводом за отдельную запись покупателя.
