description: "Почему исходящие письма идут через зашифрованную очередь в PostgreSQL по политике согласий Telegram, какие транспорты поддерживаются и что это не меняет во входе"
---

**Статус:** принято.

## Контекст

Bedolaga отправляет на почту чеки, рассылки, персональные предложения и
гостевые покупки, и операторы, переходящие с неё, ждут того же. В Omniflow был
один синхронный вызов Resend для ссылки входа и больше ничего.
[Решение 0007](/ru/architecture/decision-0007-no-customer-password) называло
отсутствие e-mail-транспорта одной из причин, почему у клиентов нет пароля;
появление транспорта снова открывает этот вопрос, если эта запись его не
закроет.

## Решение

**E-mail — канал доставки.** По нему идут чеки, уведомления об аккаунте,
реклама, на которую клиент согласился, и одноразовая ссылка входа. Это никогда
не место, куда сбрасывается выбранный клиентом секрет, и пароля у клиента
по-прежнему нет: остальные причины из 0007 — кабинет не должен отвечать «есть ли
такой адрес у клиента здесь», и каждый клиент приходит с более сильным способом
входа — действуют сами по себе.

**Всё, кроме ссылки входа, ставится в очередь в PostgreSQL** (`email_outbox`) в
той же транзакции, что и решение отправить, с ключом дедупликации, и
доставляется периодическим проходом воркера с ограниченными экспоненциальными
повторами. Без брокера, в согласии с
[0001](/ru/architecture/decision-0001-modular-monolith) и
[0002](/ru/architecture/decision-0002-postgresql-only-durability). Готовое
письмо шифруется ключом данных.

**Рекламные письма идут по политике Telegram**, а не по второй: тот же
`commerce.EvaluateDelivery`, тот же список исключений, один лимит частоты на оба
канала и согласие, хранящееся на подтверждённом адресе. В каждом рекламном
письме есть отписка в один клик по RFC 8058 без входа.

**Два транспорта: Resend и обычный SMTP.** SMTP покрывает всех остальных
провайдеров и собственные релеи; API других провайдеров не добавляются.

## Последствия

- Написать можно только на адрес, подтверждённый входом по e-mail, поэтому у
  установки без входа по e-mail нет e-mail-аудитории.
- Тихие часы на e-mail не действуют: это не push-уведомление.
- Статус доставки заканчивается на «принято транспортом». Отказы и жалобы не
  принимаются; клиента, который жалуется, оператор исключает вручную.
- Из-за шифрования панель показывает счётчики и причины, но не содержимое
  письма в очереди.

## Когда пересмотреть

Установке нужны отказы или жалобы, чтобы сохранить репутацию отправителя, —
это требует вебхука от транспорта; или для чего-либо предложен секрет,
выбранный клиентом, — тогда пересматривается 0007, а не эта запись.
