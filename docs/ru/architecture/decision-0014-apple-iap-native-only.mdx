---
title: "0014 — Встроенные покупки Apple появятся только вместе с нативным приложением"
description: "Почему Apple IAP не входит в веб-кабинет и Telegram-бот Omniflow и что должно появиться сначала"
---

**Статус:** принято.

## Контекст

Bedolaga принимает встроенные покупки Apple через своё iOS-приложение:
приложение покупает автопродлеваемую подписку через StoreKit, а сервер проверяет
транзакцию через App Store Server API и следит за App Store Server Notifications
о продлениях и возвратах.

У Omniflow нет нативного приложения. Клиентские поверхности — веб-кабинет и
Telegram-бот. Правила App Store разрешают покупки StoreKit только внутри
приложения, распространяемого через App Store; веб-страница или бот начать такую
покупку не могут.

## Решение

**Apple IAP не реализуется в Omniflow, пока нет нативного iOS-клиента.** Не
добавляются ни проверка чеков StoreKit, ни клиент App Store Server API, ни
приёмник App Store Server Notifications: каждый из них был бы недостижимым путём
оплаты, а AGENTS.md требует доводить каждую возможность до конца.

Когда нативное приложение появится, оно выйдет со своей архитектурной записью:
учётные данные App Store Server API, сопоставление транзакций и заказов, возвраты
и отзывы через уведомления, семейный доступ.

## Последствия

- Операторы, переходящие с Bedolaga с подписчиками из iOS-приложения, оставляют
  этих подписчиков на стороне App Store, пока нет нативного приложения;
  импортёр не переносит подписки App Store.
- Клиенты на iOS платят через веб-кабинет или бота другими провайдерами.

## Когда пересмотреть

В дорожную карту принят нативный клиент Omniflow для iOS (или macOS).
