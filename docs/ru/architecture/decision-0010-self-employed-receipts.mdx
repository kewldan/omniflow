---
title: "0010 — Чеки самозанятого через неофициальный API «Мой налог», изолированно и без дублей"
description: "Почему Omniflow интегрируется с неопубликованным API налоговой, как избегает дублей чеков и что могло бы это заменить"
---

**Статус:** принято.

## Контекст

Оператор-самозанятый (НПД) обязан регистрировать каждый платёж в «Мой налог».
Bedolaga делает это автоматически, и без этого операторам, переходящим с неё,
пришлось бы выбивать чеки вручную. ФНС не публикует версионированного API для
этого; все интеграции, включая Bedolaga, используют эндпоинты веб-кабинета с
паролем самого налогоплательщика.

## Решение

**Интеграция с API веб-кабинета за одним пакетом** (`internal/nalogo`), чтобы
изменение на стороне налоговой исправлялось в одном файле. Пароль и
кешированный токен зашифрованы ключом данных и больше не показываются.

**Один чек на заказ, всегда.** Строка чека уникальна по заказу. Попытка с
неизвестным исходом (таймаут, 5xx) не повторяется вслепую: следующая попытка
сначала ищет среди доходов налогоплательщика ту же сумму рядом со временем
платежа.

**Только внешние рублёвые платежи после включения интеграции** и, при желании,
только через выбранных провайдеров, чтобы провайдер, сам выдающий фискальный
чек, не получил второй.

## Последствия

- Сбой или изменение API «Мой налог» задерживает чеки на срок до двенадцати
  часов повторов, затем нужен повтор оператором; ничего не теряется.
- Возврат аннулирует чек только при полном возврате заказа; частичный возврат
  оператор исправляет вручную.
- Поиск перед повтором эвристический: два одинаковых платежа в пределах десяти
  минут могут принять один чек на двоих. Ошибка в сторону недостающего чека,
  который оператор выпустит вручную, лучше дубля, который стоит налога.

## Когда пересмотреть

ФНС открывает официальный партнёрский API для платформ НПД, доступный небольшим
операторам, или оператор фискальных данных предлагает чеки НПД по стабильному
контракту.
