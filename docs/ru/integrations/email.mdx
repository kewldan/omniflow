Omniflow отправляет письма в пяти случаях: ссылка для входа, чеки об оплате,
e-mail-рассылки, персональные предложения с отметкой «по e-mail» и гостевые
покупки. Всё это необязательно: без транспорта ничего не отправляется и ничего не
ломается.

Входа по паролю нет и не будет: e-mail — канал доставки, а не способ
аутентификации ([решение 0007](/ru/architecture/decisions#у-клиента-нет-пароля)).

## Выбор транспорта

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `APP_EMAIL_TRANSPORT` | `auto` | `resend`, `smtp` или `auto` (Resend, если задан ключ, иначе SMTP, если задан хост) |
| `APP_EMAIL_FROM` | нет | Отправитель, например `VPN <support@example.com>`. Обязателен для любого транспорта |
| `APP_RESEND_API_KEY` | нет | Ключ API Resend |
| `APP_SMTP_HOST` | нет | SMTP-сервер, например `smtp.yandex.ru` |
| `APP_SMTP_PORT` | `587` (`465` при `tls`) | Порт SMTP |
| `APP_SMTP_USERNAME`, `APP_SMTP_PASSWORD` | нет | Учётные данные SMTP. Не принимаются по незашифрованному соединению с удалённым хостом |
| `APP_SMTP_SECURITY` | `starttls` | `starttls`, `tls` (сразу TLS, порт 465) или `none` (только локальный релей) |
| `APP_EMAIL_RECEIPTS_ENABLED` | `true` | Отправлять подтверждение оплаты клиентам с подтверждённым адресом |
| `APP_EMAIL_BLOCKED_DOMAINS` | нет | Свои одноразовые домены в дополнение к встроенному списку, через запятую или пробел |

Задайте одинаковые значения для api и worker. Ссылку для входа api отправляет
сам, потому что клиент ждёт на форме; всё остальное ставится в очередь, и
доставляет воркер.

Проверить транспорт можно в **Маркетинг → Отправка e-mail**: там видно, настроен
ли транспорт, сколько писем ждёт, отправлено и не доставлено за 24 часа, и можно
отправить тестовое письмо на любой адрес.

## Как работает доставка

Каждое письмо, кроме ссылки для входа, записывается в таблицу `email_outbox` в
той же транзакции, что и решение его отправить, с ключом дедупликации: чек — по
заказу, рассылка — по кампании и клиенту, предложение — по предложению.
Повторное решение не приводит к повторному письму.

Проход воркера `email_delivery` запускается каждые 20 секунд. Временная ошибка
(сервер недоступен, Resend ограничил частоту) повторяется с экспоненциальной
задержкой от минуты, до восьми попыток примерно за девять часов. Постоянный отказ
(SMTP 5xx, Resend 400/422 на неверный адрес) не повторяется. Строки старше 90
дней удаляются.

Готовое письмо — адрес, тема, текст, ссылки — хранится зашифрованным ключом
`APP_DATA_ENCRYPTION_KEY`. В дампе базы нет ни адресов, ни ссылок в открытом
виде, и логи не называют получателя.

## Кто что получает

Клиенту можно написать только на **подтверждённый** адрес: тот, по которому он
входил через e-mail. Адрес, введённый в форму контактов, становится
подтверждённым после входа по нему.

- **Чеки** и письма об аккаунте уходят на подтверждённый адрес с включённым
  флагом «служебные». В них нет ссылки отписки: это не реклама.
- **Рассылки и предложения** уходят только на подтверждённый адрес с включённым
  флагом «маркетинг» и проходят ту же политику, что и рассылка в Telegram: список
  исключений запрещает отправку, а лимит частоты (`APP_MARKETING_FREQUENCY_CAP`
  за `APP_MARKETING_WINDOW_HOURS`) считает рекламные сообщения по **обоим**
  каналам, поэтому клиент с Telegram и e-mail не получает вдвое больше.

Получатель, которому политика отказала, записывается с причиной: `no_email`,
`no_consent`, `suppressed` или `frequency_cap`.

## E-mail-рассылки

Создайте кампанию в **Маркетинг → Кампании** и выберите канал **E-mail**. Тема и
текст шаблона берутся на языке клиента; HTML-теги Telegram удаляются.
Планирование, пауза и предпросмотр аудитории работают как для Telegram. Кампания
завершается, когда письмо каждого получателя доставлено или окончательно не
доставлено.

## Персональные предложения по e-mail

В разделе **Предложения** включите **Отправить и на e-mail**. Предложение
отправляется один раз по маркетинговой политике выше и, как и раньше, доступно в
боте и в веб-кабинете.

## Отписка в один клик

В каждом рекламном письме есть заголовок `List-Unsubscribe` вместе с
`List-Unsubscribe-Post: List-Unsubscribe=One-Click` (RFC 8058) и ссылка отписки
внизу письма. Кнопка почтового клиента отправляет POST на
`/v1/account/email/unsubscribe` без входа: в ссылке токен, подписанный ключом,
производным от `APP_DATA_ENCRYPTION_KEY`, и он умеет только отключить рассылку.
Ссылка внизу письма открывает `/unsubscribe` и просит один клик, потому что
почтовые сканеры переходят по ссылкам.

Отписка выключает флаг «маркетинг» на e-mail-адресах клиента и записывает отказ
в журнал согласий с источником `email_unsubscribe`. Чеки продолжают приходить.

## Одноразовые адреса

Вход по e-mail, добавление e-mail-контакта и гостевые покупки отклоняют адреса
сервисов временной почты (`mailinator.com`, `temp-mail.org`, `10minutemail.com` и
ещё около 250). Список встроен в программу, а не скачивается, поэтому проверка не
делает сетевых запросов; свои домены добавляются через
`APP_EMAIL_BLOCKED_DOMAINS`. Поддомен ловится по родительскому домену.
