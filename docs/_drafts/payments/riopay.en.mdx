## RioPay

RioPay (`https://api.riopay.online`, API v2.0.1) is a payment service that issues a hosted payment
link per order. The `riopay` adapter creates an order, sends the customer to its `paymentLink`, and
settles on RioPay's signed notification.

**Currency.** One currency per account, `RUB` unless `APP_RIOPAY_CURRENCY` says otherwise.

<Steps>
  <Step title="Collect the credentials">
    You need the RioPay API token and, if your account has a separate one, the webhook signing
    secret.
  </Step>
  <Step title="Configure Omniflow">
    ```env
    APP_RIOPAY_API_TOKEN=…
    # APP_RIOPAY_WEBHOOK_SECRET=…
    ```
    The adapter is registered when `APP_RIOPAY_API_TOKEN` is set. A webhook secret without a token
    fails startup.
  </Step>
  <Step title="Set the notification URL">
    In the RioPay account, point notifications at
    `https://<your-public-host>/v1/payments/webhooks/riopay`.
  </Step>
  <Step title="Pay a test order">
    Buy the cheapest plan yourself and follow it through **Verifying a provider is really working**
    on the payment providers page.
  </Step>
</Steps>

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_RIOPAY_API_TOKEN` | Yes | — | Sent as `X-Api-Token` on every API call |
| `APP_RIOPAY_WEBHOOK_SECRET` | No | the API token | HMAC-SHA512 key for notifications |
| `APP_RIOPAY_CURRENCY` | No | `RUB` | The single currency the account settles |
| `APP_RIOPAY_SUCCESS_URL` | No | — | Where the customer lands after paying, used only when an order carries no return URL of its own |

**Create.** `POST /v1/orders` with `amount` (a decimal string such as `"1499.00"`), `externalId`
(the Omniflow order ID), `purpose` (the order description), and `successUrl` (the order's return
URL). The RioPay order `id` becomes the provider reference.

**Webhook verification.** The notification is the order object, signed with HMAC-SHA512 over the
raw body, hex encoded in `X-Signature`. Omniflow compares it in constant time before reading the
body. Statuses map as `COMPLETED` → succeeded, `CANCELED` → cancelled, `FAILED` → failed, `EXPIRED`
→ expired, and `CREATED`, `PENDING`, or anything unknown → pending. Only a completed order settles,
for the amount and currency in the signed body. The event ID is `<status>:<order id>`; a verified
notification is answered with `{"status":"ok"}`.

**Polling.** Supported through `GET /v1/orders/{id}`, with the same status mapping.

**Refunds and recurring.** Not supported. There is no connection probe: RioPay offers no
read-only call that does not need an existing order.
