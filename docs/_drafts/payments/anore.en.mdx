## Anore

Anore is a hosted checkout over the Anore API (`https://api.anore.cc/v1`). Omniflow creates an
invoice, sends the customer to Anore's `paymentUrl`, and settles the order when Anore reports the
invoice paid. Amounts travel as roubles.

**Currencies:** `RUB` only.

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_ANORE_API_KEY` | Yes | — | API key, sent as a Bearer token. A key starting `an_test_` is a test key. |
| `APP_ANORE_SECRET_KEY` | Yes | — | Signing secret for outgoing requests and incoming webhooks. |
| `APP_ANORE_SHOP_ID` | For account keys | — | Positive cash-desk ID. Required when the key starts with `an_`, because an account key serves several cash desks. |
| `APP_ANORE_PAYMENT_METHODS` | No | `sbp,card,yoomoney,crypto` | Methods offered on the payment form, comma-separated. |
| `APP_ANORE_API_URL` | No | `https://api.anore.cc/v1` | API origin. |

Setting the key without the secret, an account key without a shop ID, or an unknown method fails
startup.

<Steps>
  <Step title="Configure Omniflow">
    Set `APP_ANORE_API_KEY`, `APP_ANORE_SECRET_KEY` and, for an account key, `APP_ANORE_SHOP_ID`.
    Restart the API and the worker.
  </Step>
  <Step title="Set the webhook URL">
    When `APP_PUBLIC_URL` is set, every invoice carries
    `https://<APP_PUBLIC_URL>/v1/payments/webhooks/anore` as its `callbackUrl`. Without it, set the
    same address on the cash desk in Anore.
  </Step>
</Steps>

**Requests.** Each request body is signed: `Anore-Signature` is a hex HMAC-SHA256 of the exact body
keyed with the secret. The customer's email is sent when the intent metadata carries
`customer_email`. An invoice whose answer names a different order or amount, or has no HTTPS
`paymentUrl`, is rejected. The invoice expires after Anore's `expiresIn`, or four hours when it is
absent.

**Webhook verification.** `Anore-Signature` must match the HMAC of the exact body. `Anore-Event` must
equal the signed `event`, and `Anore-Delivery-Id` must be present. Only `payment.succeeded` (status
`paid`) and `payment.expired` (status `expired`) are applied; payout events are acknowledged and
ignored. The settled amount is the invoice `amount`. A larger `rubAmount` is the customer-paid fee
and is not settled; a smaller one is rejected. The event ID is `{event}:{invoiceID}`, so a
redelivery with a new delivery ID is still a duplicate.

**Test keys.** A payment made with an `an_test_` key is never treated as paid; it is reported as
failed.

**Refunds and recurring.** Not supported.

**Polling.** Supported through `GET /payments/{id}`.

**Testing.** With an `an_test_` key, confirm that the callback reaches Omniflow and verifies. A test
payment never settles an order, so a full settlement test needs a live key.
