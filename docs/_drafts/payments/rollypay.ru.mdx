## RollyPay

RollyPay (`https://rollypay.io/api/v1`) — платёжный сервис со страницами оплаты через СБП, карты и
криптовалюту. Адаптер `rollypay` создаёт платёж, отправляет клиента по его `pay_url` и зачисляет
платёж по подписанному уведомлению RollyPay.

**Валюта.** Одна валюта на аккаунт — `RUB`, если `APP_ROLLYPAY_CURRENCY` не задаёт другую.

<Steps>
  <Step title="Получите реквизиты">
    Понадобятся API-ключ RollyPay и секрет для подписи вебхуков.
  </Step>
  <Step title="Настройте Omniflow">
    ```env
    APP_ROLLYPAY_API_KEY=…
    APP_ROLLYPAY_SIGNING_SECRET=…
    # APP_ROLLYPAY_PAYMENT_METHOD=sbp
    ```
    Адаптер регистрируется, если задано любое из двух значений, а если задано только одно, запуск
    завершается ошибкой.
  </Step>
  <Step title="Укажите URL уведомлений">
    В аккаунте RollyPay направьте уведомления на
    `https://<your-public-host>/v1/payments/webhooks/rollypay`.
  </Step>
  <Step title="Оплатите тестовый заказ">
    Купите самый дешёвый тариф сами и проверьте его по разделу **Как убедиться, что провайдер
    действительно работает** на странице платёжных провайдеров.
  </Step>
</Steps>

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `APP_ROLLYPAY_API_KEY` | Да | — | Передаётся как `X-API-Key` в каждом вызове API |
| `APP_ROLLYPAY_SIGNING_SECRET` | Да | — | Ключ HMAC-SHA256 для уведомлений |
| `APP_ROLLYPAY_CURRENCY` | Нет | `RUB` | Единственная валюта, в которой работает аккаунт |
| `APP_ROLLYPAY_PAYMENT_METHOD` | Нет | пусто | Закрепляет способ оплаты: `sbp`, `card` или `crypto`. Пустое значение оставляет выбор RollyPay |
| `APP_ROLLYPAY_RETURN_URL` | Нет | — | Куда клиент возвращается после оплаты; используется, только если у заказа нет собственного возвратного URL |

**Создание.** `POST /payments` с полями `amount` (десятичная строка, например `"1499.00"`),
`payment_currency`, `order_id` (идентификатор заказа Omniflow), `description`, `redirect_url` и
`payment_method`, если способ закреплён. Каждый вызов несёт новый случайный UUID в `X-Nonce`.
`payment_id` становится ссылкой провайдера, а `expires_at` — сроком действия оплаты.

**Проверка вебхука.** RollyPay подписывает `"<X-Timestamp>.<сырое тело>"` HMAC-SHA256 и передаёт
hex-дайджест в `X-Signature`; уведомление без метки времени или подписи отклоняется, сравнение идёт
за постоянное время. Платёж зачисляют событие `payment.paid` или статус `paid`; `processing` →
processing, `expired` → expired, `canceled` → cancelled, `chargeback` → failed, а `created` или
неизвестный статус → pending. Идентификатор события — `<event_type>:<payment_id>:<статус>`. На
проверенное уведомление отвечается `{"status":true}`.

**Опрос статуса.** Поддерживается через `GET /payments/{payment_id}`.

**Возвраты и рекуррентные платежи.** Не поддерживаются. Чарджбэк, о котором сообщает RollyPay, сам по
себе ничего в Omniflow не отменяет. Проверки подключения нет.
