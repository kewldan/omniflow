## KassaAI

KassaAI is a merchant product served by the same order API as FreeKassa (`https://api.fk.life/v1`),
with its own shop and credentials. The `kassa_ai` adapter runs alongside `freekassa` and never opens
a selection form: every checkout is an API order for one payment method — SBP by default.

**Currency.** One currency per shop, `RUB` unless `APP_KASSA_AI_CURRENCY` says otherwise.

<Steps>
  <Step title="Collect the shop credentials">
    You need the KassaAI shop ID, its API key, and secret word 2, which signs notifications.
  </Step>
  <Step title="Configure Omniflow">
    ```env
    APP_KASSA_AI_SHOP_ID=12345
    APP_KASSA_AI_API_KEY=…
    APP_KASSA_AI_SECRET_WORD_2=…
    APP_KASSA_AI_SERVER_IP=203.0.113.10
    APP_PUBLIC_URL=https://shop.example.com
    ```
    The adapter is registered when any of the four required values is set, and startup fails naming
    the missing ones when only some are.
  </Step>
  <Step title="Set the notification URL">
    With `APP_PUBLIC_URL` set, every order carries
    `https://<your-public-host>/v1/payments/webhooks/kassa_ai` as its notification URL. Without it,
    set that URL in the merchant account instead.
  </Step>
  <Step title="Pay a test order">
    Buy the cheapest plan yourself and follow it through **Verifying a provider is really working**
    on the payment providers page.
  </Step>
</Steps>

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_KASSA_AI_SHOP_ID` | Yes | — | Numeric shop ID |
| `APP_KASSA_AI_API_KEY` | Yes | — | API key. HMAC-SHA256 key for orders, status polling, and the balance probe |
| `APP_KASSA_AI_SECRET_WORD_2` | Yes | — | Verifies notifications |
| `APP_KASSA_AI_SERVER_IP` | Yes | — | Public IPv4 address of the Omniflow server, sent as the order's required `ip` field |
| `APP_KASSA_AI_PAYMENT_SYSTEM_ID` | No | `44` | Payment method: `sbp` (44, SBP QR code), `card` (36, Russian cards), `sberpay` (43, SberPay), or a numeric payment system ID |
| `APP_KASSA_AI_CURRENCY` | No | `RUB` | The single currency the shop settles |

**Create.** A JSON `POST /orders/create` with `shopId`, `nonce`, `paymentId` (the Omniflow order ID),
`i`, `email`, `ip`, `amount`, `currency`, `success_url` and `fail_url` (both the order's return URL),
and `notification_url` when `APP_PUBLIC_URL` is set. It is signed with HMAC-SHA256, keyed with the
API key, over the values sorted by key and joined with `|`. Omniflow does not pass a customer address
to KassaAI; the required `email` is sent as `user_<order ID>@telegram.org`. The customer is sent to
the `location` the API returns.

**Webhook verification.** Identical to FreeKassa: a form post with `MERCHANT_ID`, `AMOUNT`,
`MERCHANT_ORDER_ID`, `intid`, and `SIGN = md5(MERCHANT_ID:AMOUNT:secret word 2:MERCHANT_ORDER_ID)`,
checked in constant time and answered with the bare body `YES`. The event ID is `paid:<intid>`.

**Polling.** Supported through `POST /orders`; status `1` is paid, anything else stays pending.

**Refunds and recurring.** Not supported.
