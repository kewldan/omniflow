## RioPay

RioPay (`https://api.riopay.online`, API v2.0.1) — платёжный сервис, который выдаёт ссылку на оплату
для каждого заказа. Адаптер `riopay` создаёт заказ, отправляет клиента по его `paymentLink` и
зачисляет платёж по подписанному уведомлению RioPay.

**Валюта.** Одна валюта на аккаунт — `RUB`, если `APP_RIOPAY_CURRENCY` не задаёт другую.

<Steps>
  <Step title="Получите реквизиты">
    Понадобятся API-токен RioPay и, если у аккаунта он отдельный, секрет для подписи вебхуков.
  </Step>
  <Step title="Настройте Omniflow">
    ```env
    APP_RIOPAY_API_TOKEN=…
    # APP_RIOPAY_WEBHOOK_SECRET=…
    ```
    Адаптер регистрируется, когда задан `APP_RIOPAY_API_TOKEN`. Секрет вебхука без токена приводит к
    ошибке при запуске.
  </Step>
  <Step title="Укажите URL уведомлений">
    В аккаунте RioPay направьте уведомления на
    `https://<your-public-host>/v1/payments/webhooks/riopay`.
  </Step>
  <Step title="Оплатите тестовый заказ">
    Купите самый дешёвый тариф сами и проверьте его по разделу **Как убедиться, что провайдер
    действительно работает** на странице платёжных провайдеров.
  </Step>
</Steps>

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `APP_RIOPAY_API_TOKEN` | Да | — | Передаётся как `X-Api-Token` в каждом вызове API |
| `APP_RIOPAY_WEBHOOK_SECRET` | Нет | API-токен | Ключ HMAC-SHA512 для уведомлений |
| `APP_RIOPAY_CURRENCY` | Нет | `RUB` | Единственная валюта, в которой работает аккаунт |
| `APP_RIOPAY_SUCCESS_URL` | Нет | — | Куда клиент попадает после оплаты; используется, только если у заказа нет собственного возвратного URL |

**Создание.** `POST /v1/orders` с полями `amount` (десятичная строка, например `"1499.00"`),
`externalId` (идентификатор заказа Omniflow), `purpose` (описание заказа) и `successUrl` (возвратный
URL заказа). Идентификатор заказа RioPay `id` становится ссылкой провайдера.

**Проверка вебхука.** Уведомление — это объект заказа, подписанный HMAC-SHA512 от сырого тела, в hex
в заголовке `X-Signature`. Omniflow сравнивает подпись за постоянное время до чтения тела. Статусы
сопоставляются так: `COMPLETED` → succeeded, `CANCELED` → cancelled, `FAILED` → failed, `EXPIRED` →
expired, а `CREATED`, `PENDING` или неизвестный статус → pending. Зачисляется только завершённый
заказ — на сумму и в валюте из подписанного тела. Идентификатор события — `<статус>:<id заказа>`; на
проверенное уведомление отвечается `{"status":"ok"}`.

**Опрос статуса.** Поддерживается через `GET /v1/orders/{id}` с тем же сопоставлением статусов.

**Возвраты и рекуррентные платежи.** Не поддерживаются. Проверки подключения нет: у RioPay нет вызова
только на чтение, которому не нужен существующий заказ.
