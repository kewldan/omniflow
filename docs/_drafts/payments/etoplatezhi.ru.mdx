## EtoPlatezhi

EtoPlatezhi — размещённая платёжная страница (`https://paymentpage.etoplatezhi.ru/payment`).
Для открытия платежа Omniflow не обращается к API: он формирует ссылку на платёжную страницу с
подписанными параметрами и закрывает заказ по подписанному уведомлению EtoPlatezhi. Суммы
передаются целыми минорными единицами.

**Валюты:** одна валюта из `APP_ETOPLATEZHI_CURRENCY` (по умолчанию `RUB`).

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `APP_ETOPLATEZHI_PROJECT_ID` | Да | — | Положительный целочисленный ID проекта. |
| `APP_ETOPLATEZHI_SECRET_KEY` | Да | — | Секрет подписи платёжной ссылки и уведомлений. |
| `APP_ETOPLATEZHI_CURRENCY` | Нет | `RUB` | Валюта каждого платежа. |
| `APP_ETOPLATEZHI_FORCE_PAYMENT_METHOD` | Нет | пусто | `sbp` или `card`, передаётся в `force_payment_method`. Пустое значение оставляет выбор покупателю. |

<Steps>
  <Step title="Настройте Omniflow">
    Задайте `APP_ETOPLATEZHI_PROJECT_ID` и `APP_ETOPLATEZHI_SECRET_KEY`, а также `APP_PUBLIC_URL`.
    Перезапустите API и worker.
  </Step>
  <Step title="Адрес уведомлений">
    Каждая платёжная ссылка передаёт `https://<APP_PUBLIC_URL>/v1/payments/webhooks/etoplatezhi` в
    `merchant_callback_url`. Без `APP_PUBLIC_URL` адрес уведомлений не передаётся.
  </Step>
</Steps>

**Подписи.** Параметры разворачиваются в записи `ключ:значение` — вложенные ключи соединяются через
`:`, элементы списков нумеруются индексом, логические значения записываются как `1`/`0`, пустые
списки отбрасываются, `signature` и `frame_mode` пропускаются — сортируются, соединяются через `;`
и подписываются base64 HMAC-SHA512 с секретом. Уведомление несёт подпись, вычисленную так же по его
телу; она сравнивается за постоянное время, а уведомление для другого ID проекта отклоняется.

**Ссылка на заказ.** `payment.id` у EtoPlatezhi — собственный ID платежа мерчанта, поэтому ID заказа
Omniflow служит и ссылкой провайдера, и ссылкой мерчанта. ID покупателя — ID заказа, если в
метаданных намерения нет `customer_id`.

**Уведомления.** Исход определяет `payment.status`: `success` закрывает заказ по
`payment.sum.amount`; `decline` и `error` — неуспех; `cancelled`, `refunded`, `partially refunded` и
`reversed` — отмена, они никогда ничего не зачисляют; состояния ожидания и любой неизвестный статус
подтверждаются и игнорируются. ID события — `{status}:{payment.id}`.

**Возвраты, автосписания и опрос статуса.** Не поддерживаются. У исходной интеграции нет клиента
API, поэтому зачисление приходит только через уведомление, а проверки подключения нет.

**Проверка.** Откройте платёжную ссылку небольшого заказа, оплатите её и убедитесь, что уведомление
проходит проверку подписи и заказ закрывается. Тесты адаптера фиксируют обе подписи на векторах,
посчитанных исходной реализацией на Python.
