## Platega

Platega (`app.platega.io`) — платёжный шлюз для оплаты через СБП, картой и криптовалютой. Omniflow
создаёт разовую транзакцию Platega с настроенным способом оплаты и отправляет покупателя на страницу
оплаты Platega.

**Валюты:** одна валюта из `APP_PLATEGA_CURRENCY`, по умолчанию `RUB`.

### Настройка

| Переменная | Обязательна | По умолчанию | Значение |
| --- | --- | --- | --- |
| `APP_PLATEGA_MERCHANT_ID` | Да | — | ID мерчанта, передаётся как `X-MerchantId`. |
| `APP_PLATEGA_SECRET` | Да | — | Секрет API: передаётся как `X-Secret` и ожидается в каждом колбэке. Держите в секрете. |
| `APP_PLATEGA_PAYMENT_METHOD` | Нет | `2` | Код метода Platega: `2` — СБП (QR), `11` — карты (RUB), `12` — международные карты, `13` — криптовалюта. Метод должен быть включён для вашего мерчанта. `6` (подписки) не принимается. |
| `APP_PLATEGA_CURRENCY` | Нет | `RUB` | Валюта всех платежей. |
| `APP_PLATEGA_API_VERSION` | Нет | `v1` | `v1` создаёт платёж через `/transaction/process`, `v2` — через `/v2/transaction/process`. Используйте `v2`, если на v1 Platega отвечает `No available card cascades`. |
| `APP_PLATEGA_BASE_URL` | Нет | `https://app.platega.io` | Базовый адрес API. Окончание `/v1` или `/v2` выбирает эту версию. |
| `APP_PLATEGA_RETURN_URL` | Нет | — | Страница возврата, если оформление заказа её не передало. |
| `APP_PLATEGA_FAILED_URL` | Нет | страница возврата | Страница, куда Platega отправляет покупателя после неудачной оплаты. |

Если задан только один из двух ключей, запуск завершается ошибкой; если не задан ни один, Platega
выключена.

Platega требует `metadata.user_email`, который должен обозначать покупателя, а не заказ. Omniflow
передаёт e-mail покупателя или `<telegram id>@telegram.org` для покупателя, известного по Telegram ID.
Запрос на оплату без того и другого отклоняется до обращения к Platega.

<Warning>
  Оформление заказа пока не передаёт платёжным адаптерам e-mail или Telegram ID покупателя, поэтому до
  тех пор каждый платёж Platega отклоняется с этой ошибкой.
</Warning>

### Вебхук

Укажите этот адрес как URL колбэка в кабинете Platega:

```text
https://<APP_PUBLIC_URL>/v1/payments/webhooks/platega
```

Колбэк принимается, только если его заголовки `X-MerchantId` и `X-Secret` совпадают с вашими учётными
данными. Проверочный запрос кабинета — с пустым телом и без заголовков — получает ответ `200` и ничего
не меняет. `CONFIRMED` оплачивает заказ; `PENDING`, `INPROGRESS`, `FAILED`, `CANCELED`, `EXPIRED` и
любой другой статус ничего не меняют.

### Возможности

| Возможность | Поддерживается |
| --- | --- |
| Вебхуки | Да, с аутентификацией по заголовкам |
| Опрос статуса | Да, `GET /transaction/{id}` |
| Проверка подключения только на чтение | Нет |
| Возвраты | Нет |
| Рекуррентные списания | Нет. СБП-подписки Platega не используются |
| Отмена открытой транзакции | Нет |

### Проверка

1. Задайте переменные выше и перезапустите API. Ошибка запуска называет отсутствующую или неверную
   переменную.
2. Когда кабинет Platega проверяет URL колбэка, его пустой запрос появляется в `/admin` → System →
   Webhooks и получает ответ `200`.
3. Купите самую дешёвую версию тарифа сами через Platega и следите за историей платежа в
   `/admin/finance/{orderId}`. Если колбэк не пришёл, сверка прочитает статус транзакции.
