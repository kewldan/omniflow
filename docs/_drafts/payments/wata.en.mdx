## WATA

WATA (`https://api.wata.pro/api/h2h`) issues hosted payment links. The `wata` adapter creates a link
per order, sends the customer to it, and settles on WATA's RSA-signed transaction notification.

**Currency.** `RUB` only.

<Steps>
  <Step title="Collect the credentials">
    You need a WATA access token for your terminal.
  </Step>
  <Step title="Configure Omniflow">
    ```env
    APP_WATA_ACCESS_TOKEN=…
    ```
    The adapter is registered when `APP_WATA_ACCESS_TOKEN` is set.
  </Step>
  <Step title="Set the notification URL">
    In the WATA account, point notifications at
    `https://<your-public-host>/v1/payments/webhooks/wata`.
  </Step>
  <Step title="Pay a test order">
    Buy the cheapest plan yourself and follow it through **Verifying a provider is really working**
    on the payment providers page. The connection probe lists one transaction, so it checks the
    token without creating anything.
  </Step>
</Steps>

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_WATA_ACCESS_TOKEN` | Yes | — | Bearer token for every API call |
| `APP_WATA_BASE_URL` | No | `https://api.wata.pro/api/h2h` | API base URL |
| `APP_WATA_PAYMENT_TYPE` | No | `OneTime` | Sent as the link `type` |
| `APP_WATA_PAYMENT_DESCRIPTION` | No | — | Link description when an order has none of its own |
| `APP_WATA_SUCCESS_REDIRECT_URL` | No | — | Success page, used only when an order carries no return URL of its own |
| `APP_WATA_FAIL_REDIRECT_URL` | No | the order's return URL | Failure page |
| `APP_WATA_LINK_TTL_MINUTES` | No | unset | Link lifetime in minutes. Unset sends no expiry; values under 15 are raised to 15, because WATA rejects an expiry within ten minutes |
| `APP_WATA_REQUEST_TIMEOUT` | No | `30` | API timeout in seconds |
| `APP_WATA_PUBLIC_KEY_URL` | No | `<base URL>/public-key` | Where the notification-verifying public key is fetched |
| `APP_WATA_PUBLIC_KEY_CACHE_SECONDS` | No | `3600` | How long the public key is cached; `0` keeps it until restart |

**Create.** `POST /links` with `amount`, `currency`, `description`, `orderId` (the Omniflow order
ID), `type`, `successRedirectUrl`, `failRedirectUrl`, and `expirationDateTime` when a lifetime is set.
The link `id` becomes the provider reference.

**Webhook verification.** WATA signs the raw body with RSA (PKCS#1 v1.5, SHA-512) and sends the
signature base64-encoded in `X-Signature`. Omniflow verifies it against the public key WATA
publishes, fetched on first use and cached; if a refresh fails, the key already held keeps being
used. With no key at all, nothing can be verified and the notification is rejected so WATA retries.
`transactionStatus` `Paid` settles for the signed `amount`, `Declined` → failed, and anything else →
pending. The event ID is `<transactionStatus>:<transactionId>`. A verified notification is answered
with `{"status":"ok"}`.

**Polling.** Supported. `GET /links/{id}`; once the link is closed or paid, `GET /transactions`
filtered to that link and order with status `Paid`. Only a paid transaction settles, with the
transaction's amount.

**Refunds and recurring.** Not supported.
