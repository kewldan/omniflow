## Mulen Pay

Mulen Pay is a Russian payment gateway for card and SBP payments in roubles. Omniflow creates a
payment with a fiscal receipt line and sends the customer to Mulen Pay's payment page.

**Currencies:** `RUB` only.

### Configuration

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_MULENPAY_API_KEY` | Yes | — | API key, sent as `Authorization: Bearer`. Keep it secret. |
| `APP_MULENPAY_SECRET_KEY` | Yes | — | Secret key used in the SHA-1 `sign` of every payment and to check the checksum a callback may carry. Keep it secret. |
| `APP_MULENPAY_SHOP_ID` | Yes | — | Numeric shop ID from the Mulen Pay cabinet. |
| `APP_MULENPAY_BASE_URL` | No | `https://mulenpay.ru/api` | API base URL. |
| `APP_MULENPAY_LANGUAGE` | No | `ru` | Language of the payment page. |
| `APP_MULENPAY_VAT_CODE` | No | `0` | `vat_code` of the receipt line. |
| `APP_MULENPAY_PAYMENT_SUBJECT` | No | `4` | `payment_subject` of the receipt line. |
| `APP_MULENPAY_PAYMENT_MODE` | No | `4` | `payment_mode` of the receipt line. |
| `APP_MULENPAY_WEBSITE_URL` | No | `APP_PUBLIC_URL` | Sent as `website_url`. |

Setting only some of the three credentials is a startup error; setting none leaves Mulen Pay
disabled. A shop ID that is not a positive integer is a startup error.

Mulen Pay requires a payer contact (`client`) on every payment. Omniflow sends the customer's
e-mail or customer ID when the payment request carries one, and otherwise the order ID.

### Webhook

Enter this address as the callback URL in the Mulen Pay cabinet:

```text
https://<APP_PUBLIC_URL>/v1/payments/webhooks/mulenpay
```

Mulen Pay callbacks are not authenticated, so a callback never settles an order by itself. If it
carries a `sign` checksum, that checksum must be correct or the callback is rejected. Omniflow then
reads the payment through the authenticated `GET /v2/payments/{id}` and acts only on that answer:
status code `3` (success) settles, any other status changes nothing. A callback for a payment this
installation did not create is rejected without calling Mulen Pay.

### Capabilities

| Capability | Supported |
| --- | --- |
| Webhooks | Yes, confirmed by polling |
| Status polling | Yes, `GET /v2/payments/{id}` |
| Read-only connection probe | Yes, `GET /v2/payments?limit=1` |
| Refunds | No |
| Recurring charges | No |
| Cancelling an open payment | No |

### Testing

1. Set the variables above and restart the API. A startup error names a missing or malformed
   variable.
2. Optionally call `POST /v1/panel/settings/providers/mulenpay/test`. It runs the read-only probe; see
   [Verifying a provider is really working](/integrations/payments#verifying-a-provider-is-really-working)
   for where its result currently appears.
3. Buy the cheapest plan version yourself with Mulen Pay. Watch `/admin` → System → Webhooks for the
   callback and `/admin/finance/{orderId}` for the payment timeline.
