## AuraPay

AuraPay (`https://app.aurapay.tech`) is a payment service that issues hosted invoices payable by
card or SBP. The `aurapay` adapter creates an invoice, sends the customer to its payment page, and
settles on AuraPay's signed notification.

**Currency.** One currency per shop, `RUB` unless `APP_AURAPAY_CURRENCY` says otherwise.

<Steps>
  <Step title="Collect the credentials">
    You need the AuraPay API key, the shop UUID, and secret key #2, which signs notifications.
  </Step>
  <Step title="Configure Omniflow">
    ```env
    APP_AURAPAY_API_KEY=…
    APP_AURAPAY_SHOP_ID=…
    APP_AURAPAY_SECRET_KEY=…
    APP_PUBLIC_URL=https://shop.example.com
    ```
    The adapter is registered when any of the three credentials is set, and startup fails naming the
    missing ones when only some are.
  </Step>
  <Step title="Set the notification URL">
    With `APP_PUBLIC_URL` set, every invoice carries
    `https://<your-public-host>/v1/payments/webhooks/aurapay` as its `callback_url`. Without it,
    configure that URL in the AuraPay account instead.
  </Step>
  <Step title="Pay a test order">
    Buy the cheapest plan yourself and follow it through **Verifying a provider is really working**
    on the payment providers page.
  </Step>
</Steps>

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_AURAPAY_API_KEY` | Yes | — | Sent as `X-ApiKey` on every API call |
| `APP_AURAPAY_SHOP_ID` | Yes | — | Shop UUID, sent as `X-ShopId` |
| `APP_AURAPAY_SECRET_KEY` | Yes | — | Secret key #2, the HMAC-SHA256 key for notifications |
| `APP_AURAPAY_CURRENCY` | No | `RUB` | The single currency the shop settles |
| `APP_AURAPAY_PAYMENT_METHOD` | No | empty | Pins the invoice `service`: `card` or `sbp`. Empty leaves the choice to AuraPay |
| `APP_AURAPAY_PAYMENT_LIFETIME_MINUTES` | No | `60` | Invoice lifetime in minutes |
| `APP_AURAPAY_RETURN_URL` | No | — | Success and failure page, used only when an order carries no return URL of its own |

**Create.** `POST /invoice/create` with `amount`, `order_id` (the Omniflow order ID), `comment` (the
order description), `lifetime`, `success_url` and `fail_url` (the order's return URL),
`callback_url`, and `service` when a method is pinned. The invoice `id` becomes the provider
reference and `payment_data.url` the checkout link.

**Webhook verification.** AuraPay signs the notification in `X-SIGNATURE`: every top-level value,
taken in key order and converted to text, is concatenated and HMAC-SHA256'd with secret key #2. A
`null` value contributes nothing. Omniflow reproduces the text conversion of AuraPay's reference
integration, including for nested values such as payer details, and compares in constant time.
Status `PAID` settles, `EXPIRED` → expired, and `PENDING` or anything unknown → pending. The event ID
is `<status>:<invoice id>`. A verified notification is answered with `{"status":true}`.

**Polling.** Supported through `POST /invoice/status` with the invoice ID.

**Refunds and recurring.** Not supported. There is no connection probe.
