## Overpay

Hosted-checkout orders through the Overpay API (`https://api.overpay.io`) with HTTP Basic
authentication and, when the merchant was issued one, a TLS client certificate. Omniflow creates an
order with `POST /orders/`, and the customer pays on the Overpay page it links to.

**Currencies.** One: the currency the project settles in, `RUB` unless `APP_OVERPAY_CURRENCY` says
otherwise.

### Configuration

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_OVERPAY_USERNAME` | Yes | — | API user name. |
| `APP_OVERPAY_PASSWORD` | Yes | — | API password. |
| `APP_OVERPAY_PROJECT_ID` | Yes | — | Project (terminal) the orders are created in. |
| `APP_OVERPAY_CLIENT_CERT` | With the key | — | PEM client certificate (and chain) for mutual TLS. |
| `APP_OVERPAY_CLIENT_KEY` | With the certificate | — | Unencrypted PEM private key for that certificate. |
| `APP_OVERPAY_CURRENCY` | No | `RUB` | The single currency orders are sent in. |
| `APP_OVERPAY_PAYMENT_METHODS` | No | `card,fps` | Comma-separated methods offered on the payment page. |
| `APP_OVERPAY_LIFETIME_MINUTES` | No | `1440` | Order lifetime. |
| `APP_OVERPAY_API_URL` | No | `https://api.overpay.io` | API origin. |

Setting some but not all of the user name, password, and project fails startup. The certificate and
key are both set or both empty. Overpay issues the certificate as a P12 file; convert it to PEM, for
example with `openssl pkcs12 -in overpay.p12 -clcerts -nokeys` for the certificate and
`openssl pkcs12 -in overpay.p12 -nocerts -nodes` for the key. A PEM value written on one line with
literal `\n` sequences is accepted.

### Notifications

Set the notification URL in the Overpay cabinet:

```text
https://<APP_PUBLIC_URL>/v1/payments/webhooks/overpay
```

Overpay authenticates its notifications with mutual TLS terminated in front of the application, which
Omniflow cannot observe. A notification is therefore a hint: Omniflow reads `id`,
`merchantTransactionId`, and `status` from it, then re-reads the order with `GET /orders/{id}` and
applies only that answer. Only status `charged` settles, and only when the order's `amount` can be
read and matches. The event ID is `<status>:<id>`.

### Capabilities

- **Polling.** `GET /orders/{id}`.
- **Refunds.** Not supported. Overpay's refund call takes no idempotency key, and Omniflow re-asks a
  refund whose answer was lost, which could refund twice.
- **Recurring.** Not supported.
- **Connection test.** None: Overpay offers no read that proves the credentials without an existing
  order, so the panel reports the credentials as untested.

### Testing

Configure the credentials and certificate, set the notification URL, and pay a small order. Bedolaga's
SBP direct-QR flow and the separate international (EUR) terminal are not ported.
