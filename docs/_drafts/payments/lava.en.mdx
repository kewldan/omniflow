## Lava

RUB invoices through the Lava Business API (`https://api.lava.ru`). Every request is a JSON `POST`
signed with HMAC-SHA256 over the exact bytes sent, keyed by the shop's secret key and carried in the
`Signature` header. Omniflow creates an invoice with `POST /business/invoice/create`, and the customer
pays on the Lava page it links to.

**Currencies.** `RUB` only: a Lava invoice carries a rouble sum and no currency.

### Configuration

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `APP_LAVA_SHOP_ID` | Yes | — | The shop (project) UUID. |
| `APP_LAVA_SECRET_KEY` | Yes | — | The shop's secret key. Signs outgoing requests. |
| `APP_LAVA_WEBHOOK_SECRET` | Yes | — | The shop's additional key. Verifies notifications. |
| `APP_LAVA_BASE_URL` | No | `https://api.lava.ru` | API origin. |
| `APP_LAVA_PAYMENT_LIFETIME_MINUTES` | No | `60` | Invoice lifetime, clamped to Lava's 1–7200 minutes. |

`APP_PUBLIC_URL` is also required: every invoice carries its notification URL, and Lava cannot be
configured without one. Setting some but not all of the three credentials fails startup.

### Notifications

Omniflow sends the notification URL with each invoice, so nothing has to be entered in the Lava
cabinet. The URL is:

```text
https://<APP_PUBLIC_URL>/v1/payments/webhooks/lava
```

A notification must carry an `Authorization` header holding the hex HMAC-SHA256 of the body, keyed by
the additional key. Lava signs the raw body on current shops and a key-sorted re-serialisation on
shops set up for its legacy PHP SDK; a notification matching either form is accepted.

Only status `success` settles an order. The notification's rouble `amount` is compared with the
order before it does. The event ID is `<status>:<invoice_id>`.

### Capabilities

- **Polling.** `POST /business/invoice/status` by Lava's invoice ID.
- **Refunds.** Not supported: the Business API has no refund call.
- **Recurring.** Not supported. Lava subscriptions are products whose price and schedule are set in
  the Lava cabinet and charged by Lava on its own schedule, not on a merchant's request.
- **Connection test.** `POST /business/invoice/get-available-tariffs`, which lists the shop's payment
  methods and creates nothing.

### Testing

Configure the three keys and `APP_PUBLIC_URL`, run the connection test from the panel, then pay a
small order. Lava's return address must not contain a query string; Omniflow strips one from the
return URL before sending it.
