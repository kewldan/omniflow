## The default suite

`go test ./...` runs everywhere with no Docker daemon and no network. It covers the domain packages, view rendering, provider webhook parsing, backup encryption, and log redaction. Keep it that way: a suite that needs infrastructure to run is a suite that stops being run.

Alongside it CI runs TypeScript checking, frontend builds, Biome, Atlas validation, Mintlify validation, vulnerability scanning, and container builds.

## The integration suite

Tests under `internal/integrationtest` carry the `integration` build tag and start PostgreSQL through Testcontainers:

```bash
go test -tags=integration -race -timeout=20m ./internal/integrationtest/...
```

The harness applies the committed migration files in order rather than a schema dump, so the suite is a migration gate as well as a repository gate. It covers:

- migrations applying from a bare database, and the v0.4 → v0.5 adoption of existing customers onto subscriptions;
- top-up crediting the wallet exactly once across a replayed webhook, a second event, and a reconciliation;
- overpayment and underpayment resolving in the ledger while the order still settles;
- a saved cart staying saved while short and being charged once when funded;
- concurrency limits holding under simultaneous purchases;
- the outbox and the operator notice being written once per settlement;
- maintenance blocking new orders while a paid order still settles;
- the durable fulfillment job committing in the settlement transaction;
- retention removing disposable rows and never an audit event;
- operator bootstrap creating exactly one owner, and the setup token being single-use;
- sign-in answering identically for an unknown address and a wrong password, lockout after repeated failures, and the session, TOTP, and recovery-code lifecycles;
- the last active owner surviving both role revocation and suspension, and only an owner granting the owner role;
- suspension revoking live sessions, a password change sparing only the session that made it, and a reset link working once;
- audit classification, both sort directions, and keyset pages that never repeat or skip a row.

`load_test.go` is part of the same suite. It is not a throughput benchmark: it drives the same settlement, cart purchase, and subscription creation from many goroutines at once, because a duplicated charge only appears when the same work arrives from several directions simultaneously.

Running the suite is the cheapest way to catch a class of defect that compiles
and unit-tests cleanly: a Go enum widened without its database `CHECK`, an expiry
computed from the application clock while its row's `created_at` comes from the
database's, or a constraint whose derived name was guessed wrong. Each of those
only fails against a real PostgreSQL.

## Migration upgrade gate

The `migrations` CI job runs once per supported baseline — the empty database plus each prefix of the migration history — applies the rest, then applies head a second time to prove it is a no-op. A migration that cannot run on top of a released version fails there.

## What a financial change owes

New payment, wallet, authentication, RBAC, import, and Remnawave fulfillment behaviour must include focused failure-path and idempotency tests from its first implementation. In practice that means proving, for the new path:

1. The same input applied twice produces one effect.
2. A partial failure leaves no half-applied state.
3. Every rejection carries a stable machine reason, not a formatted message.

## Provider fixtures

`internal/payments/testdata` holds recorded webhook shapes with every real identifier replaced. Replaying them keeps parsing and signature verification honest without a sandbox account. Never commit a real payment payload, token, or signature — synthesise one instead.
